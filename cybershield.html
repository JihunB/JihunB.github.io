Small businesses face real website security risks (expired SSL certificates, misconfigured email authentication, exposed admin panels) but rarely have in-house security expertise or the budget for dedicated tooling. CyberShield runs a security scan in under 90 seconds, straight from a browser, and explains the results in plain language.

Midway through, I pivoted from an agent-based monitoring model to a pure domain-scanning SaaS, for lower onboarding friction and a better fit for small businesses. The site also carries 12 bilingual blog posts.

Architecture

A static front end on Vercel talks to an async FastAPI service on Railway. Supabase provides PostgreSQL, authentication and a realtime channel that pushes new findings to the dashboard.

Scan engine

Static code analyser: 14 vulnerability patterns

Users upload source files (Python, JS, PHP and others) for pattern-based static analysis. Detected categories include:

  • Hardcoded API keys and secrets, plus third-party secret patterns (Stripe, Twilio, SendGrid)
  • SQL injection through unsanitised string concatenation
  • Insecure os.getenv() fallbacks
  • JWT validation disabled (verify=False)
  • CORS wildcard (*) and debug mode left on in production
  • Insecure deserialisation (pickle.loads)
  • Open redirects through unvalidated URLs, and path traversal (../ sequences)

Security controls in the platform

A security product has to hold itself to the checks it sells. These are the controls the architecture above puts in place.

  • Tenant isolation: row-level security policies on the Supabase tables, so each customer reads only their own scans and findings.
  • Authentication: email and password or Google OAuth through Supabase Auth, with JWT-based sessions required on every dashboard API route.
  • Plan limits enforced server-side: scan quotas, file-size limits and the extended checks are gated per tier in the API, not in the browser.

Realtime updates

A Supabase Realtime WebSocket subscription pushes new scan_events to the dashboard as they land, with a silent 5-minute polling fallback when the WebSocket is unavailable. A _pollingStarted guard stops duplicate setInterval registration across the several Supabase auth events (SIGNED_IN, TOKEN_REFRESHED, INITIAL_SESSION).

Bugs resolved

Production bugs found and fixed during development, rated on my own S2 to S4 scale (S4 most severe).

Login button completely unresponsive

S4
Root cause
SyntaxError: const quota declared twice inside renderDashboard(). A syntax error stops the whole script from parsing, so no event listeners attach.
Fix
Removed the duplicate declaration. Lesson: check the browser console before assuming the bug is in the logic.

Railway deployment crashing on every push

S4
Root cause
UnboundLocalError: datetime used before assignment. A from datetime import datetime inside a function body made datetime local to the whole function under Python’s scoping rules.
Fix
Replaced agent_api.py with a lightweight deprecated stub and moved all imports to module level.

Register page jumping to step 2 while the user typed

S4
Root cause
getSession() completed while the user was still typing, and its catch(() => goStep(2)) handler advanced the step on an API failure.
Fix
Removed the auto-advance entirely; on a detected session the page now only pre-fills the email and updates the button text.

Dashboard polling every 2 seconds, causing flicker

S3
Root cause
Supabase fired three auth events per page load, and each one called startPolling(), creating independent setInterval loops.
Fix
A _pollingStarted boolean guard: polling starts exactly once per page load, however many auth events arrive.

Windows service startup timeout (agent model)

S2
Root cause
The Go process never sent the Running signal to the Windows Service Control Manager, so SCM timed out and killed the service.
Fix
Added service_windows.go with a golang.org/x/sys SCM handler.

PowerShell install script failing to parse JSON (agent model)

S2
Root cause
PowerShell’s default encoding wrote a UTF-8 byte-order mark, which Go’s json.Decoder rejects as invalid JSON.
Fix
Switched to UTF8Encoding(false) for BOM-less UTF-8 output.
